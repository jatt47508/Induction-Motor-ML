1. ABSTRACT
================================================================================

This project addresses the problem of classifying the operating condition of
an induction motor as either NORMAL or FAULT based on four sensor
measurements: voltage, current, temperature, and vibration. Using a labeled
dataset of 8,000 samples, an existing (off-the-shelf) XGBoost gradient
boosting classifier was employed to perform binary classification. The model
achieved 99.8% accuracy, 99.9% F1 score, and 1.0000 ROC-AUC on a held-out
test set of 1,600 samples. A standalone web-based demo was developed for
real-time motor health assessment.

Keywords: Induction Motor, Fault Detection, Predictive Maintenance, XGBoost,
          Binary Classification, Machine Learning

================================================================================
2. INTRODUCTION
================================================================================

2.1 BACKGROUND

Induction motors are the most widely used electric motors in industrial
applications, accounting for approximately 70-80% of total electricity
consumed in industrialized countries. Unexpected motor failures lead to
significant downtime, maintenance costs, and safety hazards. Predictive
maintenance using sensor data and machine learning offers a cost-effective
alternative to traditional scheduled maintenance.

2.2 PROBLEM STATEMENT

Given voltage, current, temperature, and vibration measurements from an
induction motor, determine whether the motor is operating normally or under
a fault condition.

2.3 OBJECTIVES

  1. Acquire and explore a labeled motor sensor dataset
  2. Preprocess the data (cleaning, encoding, scaling, splitting)
  3. Apply an existing ML model for binary classification
  4. Evaluate model performance using standard metrics
  5. Deploy a user-facing demo for real-time prediction

2.4 SCOPE

This project uses pre-existing (off-the-shelf) machine learning algorithms
as assigned. No custom neural network architectures or novel algorithms were
developed. The focus is on the end-to-end ML pipeline: data -> preprocessing
-> training -> evaluation -> deployment.

4. METHODOLOGY
================================================================================

4.1 PIPELINE OVERVIEW

  Step 1: Inspect    -> Understand raw data structure and statistics
  Step 2: Preprocess -> Clean, encode, scale, split
  Step 3: Train      -> Fit existing model on training data
  Step 4: Evaluate   -> Assess performance on unseen test data
  Step 5: Deploy     -> Web-based demo for real-time prediction

4.2 PREPROCESSING

  a) Column Renaming:
     "Voltage (V)"      -> voltage
     "Current (A)"      -> current
     "Temperature (°C)" -> temperature
     "Vibration (mm/s)" -> vibration
     "Label"            -> label

  b) Binary Label Encoding:
     The original 4-class problem was mapped to binary classification:
       normal        -> 0  (No Fault)
       low           -> 1  (Fault)
       moderate      -> 1  (Fault)
       high          -> 1  (Fault)

     Result: 2,000 normal (0) vs 6,000 fault (1)

  c) Feature Scaling:
     StandardScaler (z-score normalization) applied:
       z = (x - mean) / std
     This centers features at zero with unit variance, which benefits
     distance-based algorithms (SVM, MLP).

  d) Train/Test Split:
     Stratified 80/20 split maintaining class proportions:
       Training set: 6,400 samples (1,600 normal + 4,800 fault)
       Test set:     1,600 samples (400 normal + 1,200 fault)
     Random seed: 42 (for reproducibility)

4.3 MODEL SELECTION

  Model: XGBoost (eXtreme Gradient Boosting)

  Why XGBoost:
  - State-of-the-art for tabular/structured data
  - Handles non-linear relationships between features
  - Built-in regularization to prevent overfitting
  - Existing algorithm (no custom architecture required)
  - Industry-standard, well-documented

  Hyperparameters:
    n_estimators  = 200    (number of boosting rounds)
    max_depth     = 6      (maximum tree depth)
    learning_rate = 0.3    (default, via XGBoost API)
    eval_metric   = logloss
    random_state  = 42
    n_jobs        = -1     (use all CPU cores)

  How XGBoost Works (Brief):
  1. Builds an initial prediction (base score)
  2. Computes gradients (errors) of the loss function
  3. Builds a decision tree to fit the gradients
  4. Adds the tree to the ensemble with a learning rate weight
  5. Repeats steps 2-4 for 200 rounds
  6. Final prediction = sum of all tree outputs

4.4 ALTERNATIVE MODELS CONSIDERED

  The pipeline supports multiple existing models:

  Model              Status        Notes
  -----------------  ------------  -------------------------------

5.4 METRIC DEFINITIONS

  Accuracy  = (TP + TN) / (TP + TN + FP + FN)
              Percentage of all correct predictions

  Precision = TP / (TP + FP)
              Of all predicted faults, how many are actually faults

  Recall    = TP / (TP + FN)
              Of all actual faults, how many were detected

  F1 Score  = 2 * (Precision * Recall) / (Precision + Recall)
              Harmonic mean balancing precision and recall

  ROC-AUC   = Area Under Receiver Operating Characteristic Curve
              Measures model's ability to distinguish between classes
              1.0 = perfect, 0.5 = random guessing

  Where: TP = True Positive, TN = True Negative
         FP = False Positive, FN = False Negative

9. LIMITATIONS
================================================================================

  1. Limited Dataset: Only 8,000 samples from a single source. Real-world
     motors may exhibit different patterns.

  2. Synthetic/Simulated Data: The Kaggle dataset may be synthetic and not
     fully representative of real industrial motor behavior.

  3. Binary Simplification: Mapping 4 classes to binary loses granularity.
     A multi-class model could distinguish fault severity.

  4. Single Motor Type: Dataset represents one motor type. Different motors
     (sizes, ratings, ages) may have different normal operating ranges.

  5. No Temporal Features: Each sample is independent. Time-series patterns
     (trend, degradation rate) are not captured.

  6. Feature Limitation: Only 4 features used. Additional features like
     power factor, harmonic distortion, and speed could improve accuracy.

  7. Environment Constraint: Random Forest and LightGBM were blocked by
     Windows Application Control policy during development.
